# Feature: คัดเลือกตามลำดับโควต้า 150 คน (Selection)
Spec ID: SPEC-SEL-001 | Source: SRS v0.3 | Use case: UC-06 Owner: คณะกรรมการ | Status: Draft v2 | Updated: 2569-09-19
## Goal
คณะกรรมการคัดเลือกผู้สมัครที่กรอกข้อมูลถูกต้องตามลำดับเวลาที่สมัคร โดยจำนวนผู้ได้รับสิทธิ์รวมไม่เกิน 150 คน และระบบบันทึกรายชื่อผู้ผ่านการคัดเลือกและผู้ไม่ผ่านการคัดเลือก

## Scope
### In scope
*  แสดงรายชื่อผู้สมัครที่กรอกข้อมูลถูกต้องตามลำดับเวลาที่สมัคร
*  ระบุและยืนยันจำนวนผู้เข้าร่วมที่ต้องการคัดเลือก (ไม่เกิน 150 คน)
*  ประมวลผลคัดเลือกผู้สมัครที่กรอกข้อมูลถูกต้องตามลำดับเวลาที่สมัคร
*  ตรวจสอบจำนวนผู้ได้รับสิทธิ์ทั้งหมดต้องไม่เกิน 150 คน
*  บันทึกผลการคัดเลือกและอัปเดตสถานะผู้สมัคร
### Out of scope
*  การตรวจสอบข้อมูล/เอกสารของผู้สมัคร (ถือเป็น Precondition)
*  การประกาศผลหรือแจ้งผลการคัดเลือกไปยังนักศึกษา

## Constraints / Business Rules
- CON-SEL-01 (Quota Hard Limit): โควต้าผู้เข้าร่วมโครงการ/ค่ายถูกจำกัดไว้สูงสุดไม่เกิน 150 คนอย่างเคร่งครัด
- CON-SEL-02 (FCFS Ordering Rule): การคัดเลือกต้องดำเนินการตามลำดับก่อน-หลังของการสมัคร (First-Come, First-Served) โดยอิงตาม Timestamp การสมัคร และให้ผู้ที่สมัครก่อนอยู่ลำดับก่อน
- CON-SEL-03 (Eligibility Constraint): เฉพาะผู้สมัครที่ผ่านการตรวจสอบข้อมูล/เอกสาร (Precondition) เรียบร้อยแล้วเท่านั้น จึงจะถูกนำเข้าสู่กระบวนการคัดเลือก
- CON-SEL-04 (Audit Trail & Finality): เมื่อยืนยันผลการคัดเลือกแล้ว ระบบต้องล็อกสถานะผลการคัดเลือกและบันทึก Audit Log ระบุผู้ดำเนินการและเวลาที่กดคัดเลือก

## Requirements
*  FR-SEL-01 ระบบต้องแสดงรายชื่อผู้สมัครที่กรอกข้อมูลถูกต้องตามลำดับเวลาที่สมัคร        <- UC-06 main flow ขั้น 2
*  FR-SEL-02 คณะกรรมการระบุ/ยืนยันจำนวนผู้เข้าร่วมที่ต้องการคัดเลือก        <- UC-06 main flow ขั้น 3
*  FR-SEL-03 หากกำหนดจำนวนเกิน 150 คน ระบบต้องแจ้งเตือนและไม่อนุญาตให้ดำเนินการต่อ        <- UC-06 alternative 3a
*  FR-SEL-04 ระบบต้องดำเนินการประมวลผลคัดเลือกผู้สมัครที่กรอกข้อมูลถูกต้องตามลำดับเวลาที่สมัคร        <- UC-06 main flow ขั้น 4
*  FR-SEL-05 หากจำนวนผู้สมัครที่กรอกข้อมูลถูกต้องมีน้อยกว่า 150 คน ระบบต้องทำการคัดเลือกตามจำนวนผู้สมัครที่กรอกข้อมูลถูกต้องที่มีจริง        <- UC-06 alternative 4a
*  FR-SEL-06 ระบบต้องตรวจสอบจำนวนผู้ได้รับสิทธิ์ทั้งหมดต้องไม่เกิน 150 คน        <- UC-06 main flow ขั้น 5
*  FR-SEL-07 คณะกรรมการยืนยันผลการคัดเลือก และระบบบันทึกผลและอัปเดตสถานะผู้สมัคร        <- UC-06 main flow ขั้น 6, 7

## Quality Requirements
*  NFR-PERF-01 การประมวลผลคัดเลือกและบันทึกผลผู้สมัคร 150 คน: เวลาตอบสนอง p95 <= 2 วินาที
*  NFR-SEC-01 ข้อมูลการคัดเลือกเข้ารหัสขณะรับส่งด้วย TLS 1.2 ขึ้นไป
*  NFR-REL-01 ระบบต้องใช้ Database Transaction ในการบันทึกผลการคัดเลือก เพื่อป้องกันการอัปเดตสถานะผู้สมัครไม่สมบูรณ์

## Acceptance Criteria
*  [ ] AC-SEL-01 (FR-SEL-01, FR-SEL-02, FR-SEL-04, FR-SEL-06, FR-SEL-07) Given รายชื่อผู้สมัครที่กรอกข้อมูลถูกต้องและเรียงตามเวลาสมัครจากก่อนมาหลังเรียบร้อย When  คณะกรรมการกำหนดจำนวนคัดเลือก 150 คนและกดคัดเลือก Then  ระบบคัดเลือกผู้สมัครที่กรอกข้อมูลถูกต้องลำดับ 1-150 ให้ได้รับสิทธิ์ และบันทึกผลสำเร็จ
*  [ ] AC-SEL-02 (FR-SEL-03) Given คณะกรรมการอยู่ในหน้าคัดเลือกผู้เข้าร่วมค่าย When  กำหนดจำนวนคัดเลือกเกิน 150 คน Then  ระบบแจ้งเตือนและไม่อนุญาตให้ดำเนินการต่อ
*  [ ] AC-SEL-03 (FR-SEL-05) Given มีผู้สมัครที่กรอกข้อมูลถูกต้องน้อยกว่า 150 คน (เช่น 120 คน) When  คณะกรรมการระบุจำนวนคัดเลือก 150 คนและกดคัดเลือก Then  ระบบทำการคัดเลือกผู้สมัครที่กรอกข้อมูลถูกต้องตามจำนวนที่มีจริง (120 คน) โดยเรียงจากผู้ที่สมัครก่อนมาหลัง
*  [ ] AC-SEL-04 (NFR-PERF-01) Given มีผู้สมัครที่กรอกข้อมูลถูกต้อง 150 คน When  ระบบประมวลผลคัดเลือกและบันทึกสถานะผู้สมัคร Then  เวลาตอบสนอง p95 ต้องไม่เกิน 2 วินาที
*  [ ] AC-SEL-05 (NFR-SEC-01) Given การสื่อสารระหว่างผู้ใช้กับระบบในกระบวนการคัดเลือก When  ข้อมูลการคัดเลือกถูกส่งหรือรับ Then  ระบบต้องใช้ TLS 1.2 ขึ้นไปในการเข้ารหัสข้อมูล
*  [ ] AC-SEL-06 (NFR-REL-01) Given ระบบกำลังยืนยันผลการคัดเลือก When  มีการอัปเดตสถานะผู้สมัครและบันทึกผล Then  ระบบต้องใช้ Database Transaction เพื่อให้การบันทึกเป็นไปอย่างสมบูรณ์และไม่อัปเดตสถานะแบบครึ่งหนึ่ง

## Assumptions & Open Questions
*  ASM-01 ผู้สมัครผ่านการตรวจสอบข้อมูล/เอกสาร และถูกจัดเรียงลำดับเรียบร้อยแล้วก่อนเริ่มกระบวนการคัดเลือก
*  ASM-02 ลำดับการสมัครใช้วันและเวลาบันทึกการสมัคร (Timestamp) ในระบบ
*  ASM-03 ผู้สมัครที่นำเข้าสู่กระบวนการคัดเลือกคือผู้สมัครที่กรอกข้อมูลถูกต้องและผ่านการตรวจสอบแล้ว
*  ASM-04 ระบบคัดเลือกผู้สมัครตามจำนวนที่กรอกข้อมูลถูกต้องจริง แต่จำนวนผู้ได้รับสิทธิ์ต้องไม่เกิน 150 คน
*  ASM-05 การเรียงลำดับใช้เวลาสมัคร โดยผู้ที่สมัครก่อนต้องอยู่ก่อนผู้ที่สมัครภายหลัง
*  ASM-06 หากมีผู้สมัครหลายคนมี Timestamp เดียวกัน ระบบต้องใช้ลำดับการสมัครที่ระบบบันทึกไว้เป็นลำดับสำรอง เพื่อจัดลำดับผู้สมัครให้แน่นอน
*  ASM-07 หากจำนวนที่ระบุสูงกว่าจำนวนผู้สมัครที่ผ่านเกณฑ์ แต่ไม่เกิน 150 คน ระบบจะคัดเลือกผู้สมัครที่ผ่านเกณฑ์ทั้งหมดที่มีอยู่ และไม่ต้องแจ้งเตือนให้แก้จำนวน
*  ASM-08 “ผู้สมัครที่ผ่านเกณฑ์” หมายถึงผู้สมัครที่ผ่านการตรวจสอบข้อมูล/เอกสารตาม CON-SEL-03
*  ASM-09 เมื่อคณะกรรมการยืนยันผลแล้ว ระบบต้องป้องกันการแก้ไขหรือลบผลการคัดเลือกโดยตรง และควรบันทึก Audit Log อย่างน้อย ได้แก่ ผู้ดำเนินการ, วัน/เวลา, รายการที่ดำเนินการ, และผลการดำเนินการ
*  Q-01 หากผู้ได้รับสิทธิ์สละสิทธิ์ในภายหลัง ระบบต้องมีฟังก์ชันเรียกคิวสำรองหรือไม่? -> ถามคณะกรรมการ
