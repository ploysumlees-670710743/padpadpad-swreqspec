# Feature: จัดการตารางกิจกรรมและ checklist (Schedule Management)
Spec ID: SPEC-SCH-001 | Source: SRS v0.3 | Use case: UC-05 Owner: คณะกรรมการ | Status: Draft v1 | Updated: 2569-09-19
## Goal
คณะกรรมการสร้างและปรับแต่งตารางกิจกรรมประจำวันภายในค่าย เพื่อจัดทำกำหนดการกิจกรรมที่ชัดเจนสำหรับนักศึกษาและอาจารย์

## Scope
### In scope
*  แสดงเมนูกิจกรรมค่ายและรองรับการเพิ่ม/แก้ไขกิจกรรมย่อยในตาราง
*  กำหนดวัน ช่วงเวลาเริ่ม-สิ้นสุด สถานที่ รายละเอียด และวิทยากร/ผู้รับผิดชอบ
*  ตรวจสอบความซ้ำซ้อนของเวลาและสถานที่จัดกิจกรรมย่อยโดยอัตโนมัติ
*  บันทึกตารางกิจกรรมค่ายลงในระบบ
### Out of scope
*  การสร้างข้อมูลโครงการค่ายและสถานที่จัดค่าย (ถือเป็น Precondition)
*  การประกาศผลหรือส่งแจ้งเตือนการเปลี่ยนแปลงตารางกิจกรรมไปยังนักศึกษา/อาจารย์เรียลไทม์

## Constraints / Business Rules
- CON-SCH-01 (No Time & Location Overlap): ระบบต้องไม่ยินยอมให้บันทึกกิจกรรมย่อยที่มีช่วงเวลาและสถานที่ซ้อนทับกับกิจกรรมอื่นในค่าย
- CON-SCH-02 (Precondition Dependency): การจัดทำตารางกิจกรรมต้องอิงตามข้อมูลโครงการค่ายและสถานที่จัดค่ายที่มีอยู่ในระบบแล้วเท่านั้น
- CON-SCH-03 (Role-Based Access): เฉพาะผู้ใช้งานบทบาทคณะกรรมการเท่านั้นที่มีสิทธิ์จัดการเพิ่มหรือแก้ไขตารางกิจกรรม

## Requirements
*  FR-SCH-01 ระบบต้องแสดงเมนูและตารางกิจกรรมค่าย เพื่อให้คณะกรรมการเลือกเพิ่มหรือแก้ไขกิจกรรมย่อย        <- UC-05 main flow ขั้น 1, 2
*  FR-SCH-02 ระบบต้องอนุญาตให้กำหนดวัน ช่วงเวลาเริ่ม-สิ้นสุด สถานที่ รายละเอียด และวิทยากร/ผู้รับผิดชอบ        <- UC-05 main flow ขั้น 3, 4, 5
*  FR-SCH-03 ระบบต้องตรวจสอบความซ้ำซ้อนของช่วงเวลาและสถานที่จัดกิจกรรมย่อยก่อนทำการบันทึก        <- UC-05 main flow ขั้น 6
*  FR-SCH-04 หากเวลาหรือสถานที่ของกิจกรรมย่อยซ้อนทับกัน ระบบต้องแสดงข้อความแจ้งเตือนให้เปลี่ยนช่วงเวลา และไม่อนุญาตให้บันทึก        <- UC-05 alternative 6a
*  FR-SCH-05 เมื่อตรวจสอบไม่พบความซ้ำซ้อน ระบบต้องบันทึกตารางกิจกรรมเข้าสู่ตารางค่ายสำเร็จ        <- UC-05 main flow ขั้น 7

## Quality Requirements
*  NFR-PERF-01 การตรวจสอบความซ้ำซ้อนของเวลาและสถานที่ และการบันทึกตารางกิจกรรม: เวลาตอบสนอง p95 <= 1 วินาที
*  NFR-SEC-01 เฉพาะผู้ใช้สิทธิ์คณะกรรมการเท่านั้นที่สามารถเพิ่ม แก้ไข หรือบันทึกตารางกิจกรรมได้
*  NFR-REL-01 ระบบต้องใช้ Database Transaction ในการบันทึกตารางกิจกรรม เพื่อป้องกันข้อมูลสูญหายหรือบันทึกไม่ครบถ้วน

## Acceptance Criteria
*  [ ] AC-SCH-01 (FR-SCH-01, FR-SCH-02, FR-SCH-03, FR-SCH-05) Given คณะกรรมการอยู่ในหน้าจัดการตารางกิจกรรม When  กรอกชื่อกิจกรรม ช่วงเวลา สถานที่ และกดบันทึก Then  ระบบตรวจสอบว่าตารางไม่ซ้อนทับ และบันทึกกิจกรรมเข้าสู่ตารางค่าย
*  [ ] AC-SCH-02 (FR-SCH-04) Given คณะกรรมการกำลังเพิ่มหรือแก้ไขกิจกรรมย่อย When  กรอกช่วงเวลาและสถานที่ซึ่งซ้อนทับกับกิจกรรมอื่นที่มีอยู่แล้ว Then  ระบบแสดงข้อความแจ้งเตือนให้เปลี่ยนช่วงเวลา และไม่อนุญาตให้บันทึก

## Assumptions & Open Questions
*  ASM-01 ข้อมูลโครงการค่ายและสถานที่จัดค่ายได้รับการตั้งค่าในระบบเรียบร้อยแล้ว
*  ASM-02 การซ้อนทับของสถานที่นับเฉพาะกิจกรรมที่ใช้สถานที่เดียวกันในช่วงเวลาเดียวกัน
*  Q-01 ในส่วน checklist ของกิจกรรมย่อย ระบบต้องบันทึกสถานะการทำเสร็จ (Done/Pending) ด้วยหรือไม่? -> ถามคณะกรรมการ
