# แผนทางเทคนิค: UC-09 เข้าสู่ระบบ

## 1. สรุปแนวทาง

1. สร้างหน้า Login สำหรับนักศึกษา คณะกรรมการ และอาจารย์ตาม FR-LOG-01 และ FR-LOG-02
2. ตรวจสอบ Username, Password และสถานะบัญชี Active ตาม FR-LOG-03
3. ตรวจสอบบทบาทที่อนุญาตเฉพาะนักศึกษา คณะกรรมการ และอาจารย์ตาม FR-LOG-04
4. นำผู้ใช้ที่ผ่านการตรวจสอบไปยังหน้าหลักพร้อมเมนูตามบทบาทตาม FR-LOG-05 และ AC-LOG-01
5. แสดงผลลัพธ์ที่แตกต่างกันสำหรับข้อมูลผิดและบัญชีไม่มีสิทธิ์ตาม FR-LOG-06, FR-LOG-07, AC-LOG-02 และ AC-LOG-03

## 2. เทคโนโลยีที่ใช้

| สิ่งที่เลือก | มาจาก | หมายเหตุ |
| :--- | :--- | :--- |
| React (Vite) | ทีมเลือกเอง ไม่ได้มาจาก spec | ใช้สร้างหน้า Login และหน้าหลักตาม FR-LOG-01, FR-LOG-05 |
| Python FastAPI | ทีมเลือกเอง ไม่ได้มาจาก spec | ใช้รับคำขอเข้าสู่ระบบและตรวจสอบบัญชีตาม FR-LOG-03, FR-LOG-04 |
| ฐานข้อมูลเชิงสัมพันธ์ | ทีมเลือกเอง ไม่ได้มาจาก spec | ใช้เก็บข้อมูลบัญชีตาม ASM-LOG-01 และตรวจสอบข้อมูลตาม FR-LOG-03 |

## 3. โมเดลข้อมูล

| Entity | ฟิลด์หลัก | รองรับ |
| :--- | :--- | :--- |
| UserAccount | username, password, status, role | FR-LOG-02, FR-LOG-03, FR-LOG-04, ASM-LOG-01, ASM-LOG-02, ASM-LOG-03 |
| RoleMenu | role, menu | FR-LOG-05, AC-LOG-01 |

`UserAccount.status` ต้องรองรับสถานะ Active และสถานะถูกระงับตาม FR-LOG-03, FR-LOG-07 และ AC-LOG-03 ฟิลด์ข้อมูลอื่นนอกเหนือจากที่ระบุใน spec จะยังไม่กำหนดเพิ่มเติม

## 4. API / หน้าจอ

- `GET /login`: แสดงหน้าเข้าสู่ระบบตาม FR-LOG-01; input/output หลักคือหน้า Login ที่มีช่อง Username และ Password
- `POST /login`: รับ Username และ Password ตาม FR-LOG-02; ตรวจสอบข้อมูลและสถานะบัญชีตาม FR-LOG-03 และตรวจสอบบทบาทตาม FR-LOG-04; output คือผลสำเร็จพร้อม role หรือผลปฏิเสธตาม FR-LOG-06 และ FR-LOG-07
- `GET /home`: แสดงหน้าหลักและเมนูตาม role ตาม FR-LOG-05 และ AC-LOG-01; output คือเมนูของนักศึกษา คณะกรรมการ หรืออาจารย์ตามบทบาท
- `LoginErrorState`: คงผู้ใช้ไว้ที่หน้า Login และแสดงข้อความ “ชื่อผู้ใช้หรือรหัสผ่านไม่ถูกต้อง” ตาม FR-LOG-06 และ AC-LOG-02 หรือ “บัญชีของคุณไม่มีสิทธิ์เข้าใช้งานระบบ” ตาม FR-LOG-07 และ AC-LOG-03

## 6. แผนทดสอบจาก Acceptance Criteria

| AC ID | ชื่อ test | ทดสอบอย่างไร |
| :--- | :--- | :--- |
| AC-LOG-01 | `test_AC_LOG_01_login_success_by_role` | ส่ง Username และ Password ของบัญชี Active ที่มีแต่ละบทบาท ตรวจว่าระบบนำไปหน้าหลักและแสดงเมนูตรงกับบทบาทตาม AC-LOG-01 และ FR-LOG-05 |
| AC-LOG-02 | `test_AC_LOG_02_invalid_credentials` | ส่ง Username หรือ Password ไม่ถูกต้อง ตรวจข้อความ “ชื่อผู้ใช้หรือรหัสผ่านไม่ถูกต้อง” และตรวจว่ายังคงอยู่ที่หน้า Login ตาม AC-LOG-02 และ FR-LOG-06 |
| AC-LOG-03 | `test_AC_LOG_03_unauthorized_account` | ส่งข้อมูลของบัญชีที่มีบทบาทนอกเหนือจาก 3 บทบาทหรือถูกระงับ ตรวจข้อความ “บัญชีของคุณไม่มีสิทธิ์เข้าใช้งานระบบ” ไม่ไปหน้า Dashboard และคงอยู่ที่หน้า Login ตาม AC-LOG-03 และ FR-LOG-07 |

## 7. ลำดับงาน

1. สร้างหน้า Login และช่อง Username/Password ตาม FR-LOG-01 และ FR-LOG-02
2. จัดเตรียมโมเดล UserAccount สำหรับ username, password, status และ role ตาม FR-LOG-03, FR-LOG-04 และ ASM-LOG-01
3. สร้างการตรวจสอบข้อมูลบัญชีและสถานะ Active ตาม FR-LOG-03 และ ASM-LOG-02
4. สร้างการตรวจสอบบทบาทที่อนุญาตตาม FR-LOG-04 และ ASM-LOG-03
5. สร้างการนำทางไปหน้าหลักและการแสดงเมนูตามบทบาทตาม FR-LOG-05 และ AC-LOG-01
6. สร้างผลลัพธ์ข้อมูลไม่ถูกต้องและการคงหน้า Login ตาม FR-LOG-06 และ AC-LOG-02
7. สร้างผลลัพธ์บัญชีไม่มีสิทธิ์และการคงหน้า Login ตาม FR-LOG-07 และ AC-LOG-03
8. ทดสอบ AC-LOG-01, AC-LOG-02 และ AC-LOG-03 ตามตารางแผนทดสอบ
