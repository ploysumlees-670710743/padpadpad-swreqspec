# Feature: จัดการตารางกิจกรรมและ checklist (Schedule Management)
Spec ID: SPEC-SCH-005 | Source: SRS v0.3 | Use case: UC-05 Owner: คณะกรรมการ | Status: Draft v2 | Updated: 2569-09-20
## Goal
คณะกรรมการสร้างและปรับแต่งตารางกิจกรรมประจำวันภายในค่าย เพื่อจัดทำกำหนดการกิจกรรมที่ชัดเจนสำหรับนักศึกษาและอาจารย์

## Scope
### In scope
*  แสดงเมนูกิจกรรมค่ายและรองรับการเพิ่ม/แก้ไขกิจกรรมย่อยในตาราง
*  กำหนดวัน ช่วงเวลาเริ่ม-สิ้นสุด สถานที่ รายละเอียด และวิทยากร/ผู้รับผิดชอบ
*  ตรวจสอบความซ้ำซ้อนของเวลาและสถานที่จัดกิจกรรมย่อยโดยอัตโนมัติ
*  บันทึกตารางกิจกรรมค่ายลงในระบบ
### Out of scope
*  การสร้างข้อมูลโครงการค่ายและสถานที่จัดค่าย (ถือเป็น Precondition)
*  การประกาศผลหรือส่งแจ้งเตือนการเปลี่ยนแปลงตารางกิจกรรมไปยังนักศึกษา/อาจารย์เรียลไทม์

## Constraints / Business Rules
- CON-SCH-01 (No Time & Location Overlap): ระบบต้องไม่ยินยอมให้บันทึกกิจกรรมย่อยที่มีช่วงเวลาและสถานที่ซ้อนทับกับกิจกรรมอื่นในค่าย โดยกิจกรรมที่ใช้สถานที่เดียวกันแต่ช่วงเวลาไม่ซ้อนทับกันสามารถบันทึกได้
- CON-SCH-02 (Precondition Dependency): การจัดทำตารางกิจกรรมต้องอิงตามข้อมูลโครงการค่ายและสถานที่จัดค่ายที่มีอยู่ในระบบแล้วเท่านั้น
- CON-SCH-03 (Role-Based Access): เฉพาะผู้ใช้งานที่มีสิทธิ์จัดการตารางกิจกรรมเท่านั้นที่มีสิทธิ์เพิ่ม แก้ไข หรือลบกิจกรรมย่อย โดยคณะกรรมการเป็นผู้มีสิทธิ์ดังกล่าวตามบทบาท ส่วนอาจารย์และเจ้าหน้าที่ฝ่ายงานมีสิทธิ์ดูตารางได้แต่ไม่มีสิทธิ์แก้ไขหรือลบ เว้นแต่ระบบมอบสิทธิ์ให้เป็นผู้จัดการข้อมูลกิจกรรม

## Requirements
*  FR-SCH-01 ระบบต้องแสดงเมนูและตารางกิจกรรมค่าย เพื่อให้ผู้ที่มีสิทธิ์จัดการตารางกิจกรรมเลือกเพิ่ม แก้ไข หรือลบกิจกรรมย่อย และบันทึก/แสดงสถานะ checklist ของกิจกรรมย่อยเป็น Done หรือ Pending        <- UC-05 main flow ขั้น 1, 2
*  FR-SCH-02 ระบบต้องอนุญาตให้กำหนดวัน ช่วงเวลาเริ่ม-สิ้นสุด สถานที่ รายละเอียด และวิทยากร/ผู้รับผิดชอบ โดยต้องกรอกทั้งรายละเอียดและวิทยากร/ผู้รับผิดชอบทุกกิจกรรมย่อย หากไม่มีวิทยากรให้กรอกชื่อผู้รับผิดชอบแทน        <- UC-05 main flow ขั้น 3, 4, 5
*  FR-SCH-03 ระบบต้องตรวจสอบความซ้ำซ้อนของช่วงเวลาและสถานที่จัดกิจกรรมย่อยก่อนทำการบันทึก        <- UC-05 main flow ขั้น 6
*  FR-SCH-04 หากช่วงเวลาและสถานที่ของกิจกรรมย่อยซ้อนทับกัน ระบบต้องปฏิเสธการบันทึกและแสดงข้อความแจ้งเตือนบริเวณข้อมูลที่เกิดความซ้ำซ้อน เพื่อให้ผู้ใช้แก้ไขก่อนบันทึก        <- UC-05 alternative 6a
*  FR-SCH-05 เมื่อตรวจสอบไม่พบความซ้ำซ้อน ระบบต้องบันทึกตารางกิจกรรมเข้าสู่ตารางค่ายสำเร็จ        <- UC-05 main flow ขั้น 7

## Quality Requirements
*  NFR-PERF-01 การตรวจสอบความซ้ำซ้อนของเวลาและสถานที่ และการบันทึกตารางกิจกรรม: เวลาตอบสนอง p95 <= 1 วินาที
*  NFR-SEC-01 เฉพาะผู้ใช้ที่ได้รับสิทธิ์จัดการตารางกิจกรรมเท่านั้นที่สามารถเพิ่ม แก้ไข ลบ หรือบันทึกตารางกิจกรรมได้ ส่วนอาจารย์และเจ้าหน้าที่ฝ่ายงานที่ไม่มีสิทธิ์จัดการสามารถดูตารางได้เท่านั้น
*  NFR-REL-01 ระบบต้องใช้ Database Transaction ในการบันทึกตารางกิจกรรม เพื่อป้องกันข้อมูลสูญหายหรือบันทึกไม่ครบถ้วน

## Acceptance Criteria
*  [ ] AC-SCH-01 (FR-SCH-01, FR-SCH-02, FR-SCH-03, FR-SCH-05) Given ผู้ใช้ที่มีสิทธิ์จัดการอยู่ในหน้าจัดการตารางกิจกรรม When  กรอกชื่อกิจกรรม วัน ช่วงเวลา สถานที่ รายละเอียด และวิทยากร/ผู้รับผิดชอบครบถ้วน แล้วกดบันทึก Then  ระบบตรวจสอบว่าตารางไม่ซ้อนทับ บันทึกกิจกรรมเข้าสู่ตารางค่าย แสดงสถานะ checklist ของกิจกรรมเป็น Pending และรองรับการติดตามสถานะ Done/Pending
*  [ ] AC-SCH-02 (FR-SCH-04) Given ผู้ใช้ที่มีสิทธิ์จัดการกำลังเพิ่มหรือแก้ไขกิจกรรมย่อย When  กรอกช่วงเวลาและสถานที่ซึ่งซ้อนทับกับกิจกรรมอื่นที่มีอยู่แล้ว Then  ระบบปฏิเสธการบันทึกและแสดงข้อความแจ้งเตือนบริเวณข้อมูลช่วงเวลา/สถานที่ที่ซ้ำซ้อน เพื่อให้ผู้ใช้แก้ไขก่อนบันทึก

## Assumptions & Open Questions
*  ASM-01 ข้อมูลโครงการค่ายและสถานที่จัดค่ายได้รับการตั้งค่าในระบบเรียบร้อยแล้ว
*  ASM-02 การซ้อนทับของสถานที่นับเฉพาะกิจกรรมที่ใช้สถานที่เดียวกันในช่วงเวลาเดียวกัน กิจกรรมที่ใช้สถานที่เดียวกันแต่ช่วงเวลาไม่ซ้อนทับกันสามารถบันทึกได้
*  ASM-03 ทุกกิจกรรมย่อยต้องมีรายละเอียดและวิทยากร/ผู้รับผิดชอบ หากไม่มีวิทยากรให้ใช้ชื่อผู้รับผิดชอบแทน
*  ASM-04 กิจกรรมย่อยที่สร้างใหม่มีสถานะ checklist เป็น Pending และสามารถติดตามสถานะ Done/Pending ได้
*  ASM-05 การเพิ่ม แก้ไข หรือลบกิจกรรมย่อยทำได้เฉพาะผู้ที่ระบบมอบสิทธิ์จัดการตารางกิจกรรม ส่วนอาจารย์และเจ้าหน้าที่ฝ่ายงานที่ไม่มีสิทธิ์จัดการดูตารางได้เท่านั้น
