# แผนงาน: แก้ไขข้อมูลผู้สมัคร

## 1. สรุปแนวทาง
- ฟีเจอร์นี้ช่วยให้คณะกรรมการค้นหาและแก้ไขข้อมูลผู้สมัครที่มีอยู่แล้ว โดยยึดหลักความถูกต้องของข้อมูลและการตรวจสอบย้อนหลังผ่าน Audit Log
- ผู้ใช้งานหลักคือ คณะกรรมการ และผู้ดูแลระบบ ที่มีสิทธิ์ตาม SEC-RBAC-01
- ระบบจะเปิดหน้าจอแก้ไขข้อมูลแบบมีข้อมูลเดิมให้ตรวจสอบก่อนบันทึก และใช้ validation ก่อนยืนยันการอัปเดต
- เมื่อข้อมูลผ่านเงื่อนไข ระบบจะบันทึกข้อมูลใหม่ภายใต้ transaction เดียวกันกับการสร้าง Audit Log เพื่อให้มั่นใจว่าไม่มีการอัปเดตแบบไม่สมบูรณ์
- หากผู้ใช้ยกเลิกหรือข้อมูลไม่ถูกต้อง ระบบจะไม่บันทึกอย่างใดและคืนค่าตามข้อมูลเดิมให้ผู้ใช้เห็น

## 2. เทคโนโลยีที่ใช้

| สิ่งที่เลือก | มาจาก | หมายเหตุ |
|---|---|---|
| React + Vite สำหรับหน้าบ้าน | ทีมเลือกเอง ไม่ได้มาจาก spec | ใช้สำหรับหน้าจอค้นหา/แก้ไขข้อมูลผู้สมัคร |
| Python FastAPI สำหรับหลังบ้าน | ทีมเลือกเอง ไม่ได้มาจาก spec | ใช้สำหรับ API ตรวจสอบข้อมูล, บันทึกข้อมูล, และสร้าง Audit Log |
| Browser form validation + server-side validation | FR-REG-02, FR-REG-03, NFR-USE-01 | ใช้ทั้งการแจ้งเตือนบนหน้า และการตรวจซ้ำที่ backend |
| Transactional database update | DOM-TXN-01 | จัดการอัปเดตข้อมูลผู้สมัครและ Audit Log ใน transaction เดียวกัน |

## 3. โมเดลข้อมูล

### 3.1 Applicant
| ฟิลด์หลัก | คำอธิบาย | รองรับ |
|---|---|---|
| applicant_id | รหัสผู้สมัคร | FR-REG-01, FR-REG-04 |
| full_name | ชื่อ-นามสกุลผู้สมัคร | FR-REG-02, FR-REG-04 |
| phone_number | เบอร์โทรศัพท์ติดต่อ | FR-REG-02, FR-REG-04 |
| email | อีเมลติดต่อ | FR-REG-02, FR-REG-04 |
| address | ที่อยู่/ข้อมูลประกอบ | FR-REG-02, FR-REG-04 |
| status | สถานะการลงทะเบียน/สมัคร | FR-REG-01, FR-REG-06 |
| updated_at | เวลาที่อัปเดตล่าสุด | FR-REG-04, FR-REG-05 |

### 3.2 UserAccount
| ฟิลด์หลัก | คำอธิบาย | รองรับ |
|---|---|---|
| user_id | รหัสผู้ใช้ | SEC-RBAC-01 |
| role | บทบาท: คณะกรรมการ หรือ ผู้ดูแลระบบ | SEC-RBAC-01 |
| display_name | ชื่อผู้ใช้งาน | FR-REG-05 |

### 3.3 AuditLog
| ฟิลด์หลัก | คำอธิบาย | รองรับ |
|---|---|---|
| audit_id | รหัสบันทึก Audit Log | DOM-AUD-01 |
| applicant_id | ผู้สมัครที่ถูกแก้ไข | FR-REG-05 |
| editor_user_id | ผู้ที่ทำการแก้ไข | FR-REG-05 |
| edited_at | วันเวลาแก้ไข | FR-REG-05, DOM-AUD-01 |
| field_name | ฟิลด์ที่เปลี่ยนแปลง | FR-REG-05 |
| old_value | ค่าเดิม | FR-REG-05, DOM-AUD-01 |
| new_value | ค่าใหม่ | FR-REG-05, DOM-AUD-01 |
| change_summary | สรุปการเปลี่ยนแปลงแบบย่อ | FR-REG-05 |

> ข้อมูลที่ห้าม/ไม่ใช้ในโมเดลนี้: ไม่มีฟิลด์ที่เก็บเลขประจำตัวประชาชนหรือรหัสผู้สมัครที่ถูกปรับเปลี่ยนได้ในฟีเจอร์นี้ เนื่องจาก spec ยังไม่ได้ระบุให้เป็นฟิลด์ที่อนุญาตให้แก้ไข และทีมยืนยันว่ามีการเก็บ log ของการแก้ไขไว้ทุกครั้ง

## 4. API / หน้าจอ

- GET /applicants/{applicant_id}/edit — หน้าแก้ไขข้อมูลผู้สมัคร; input: applicant_id; output: ข้อมูลเดิมพร้อมฟิลด์ที่สามารถแก้ไขได้; รองรับ FR-REG-01
- POST /applicants/{applicant_id}/validate — ตรวจสอบข้อมูลใหม่ก่อนบันทึก; input: payload ข้อมูลฟอร์ม; output: รายการข้อผิดพลาดหรือผ่าน validation; รองรับ FR-REG-02, FR-REG-03
- PUT /applicants/{applicant_id} — บันทึกข้อมูลใหม่หลังยืนยัน; input: payload ที่ต้องการอัปเดต; output: สถานะสำเร็จ/ล้มเหลว; รองรับ FR-REG-04, FR-REG-05, DOM-TXN-01
- POST /applicants/{applicant_id}/cancel-edit — ยกเลิกการแก้ไขและคืนค่าเดิม; input: applicant_id; output: สถานะยกเลิกพร้อมปิดฟอร์ม; รองรับ FR-REG-06
- GET /applicants/{applicant_id}/audit-log — ดึงประวัติการเปลี่ยนแปลง; input: applicant_id; output: AuditLog list; รองรับ DOM-AUD-01
- UI page: /applicants/:id/edit — หน้าจอแก้ไขข้อมูลพร้อม highlight ช่องที่ผิดพลาด และข้อความแจ้งเตือนตาม NFR-USE-01

## 5. ตารางตรวจ Constraints

| Constraint ID | ถูกนำไปใช้ที่ไหนใน plan | สถานะ |
|---|---|---|
| DOM-AUD-01 | AuditLog entity และ API GET/PUT /applicants/{applicant_id}/audit-log; บันทึกผู้แก้ไข วันเวลา ค่าเดิม ค่าใหม่ | ใช้แล้ว |
| DOM-TXN-01 | PUT /applicants/{applicant_id} ให้ update Applicant และ insert AuditLog ใน transaction เดียวกัน | ใช้แล้ว |
| SEC-RBAC-01 | UserAccount role และการป้องกันการเข้าถึงหน้าจอ/endpoint สำหรับคณะกรรมการหรือผู้ดูแลระบบ | ใช้แล้ว |

## 7. ลำดับงาน

1. สร้างหน้าและ route สำหรับค้นหา/เปิดฟอร์มแก้ไขข้อมูลผู้สมัคร (FR-REG-01, AC-REG-01)
2. สร้าง schema และ API สำหรับดึงข้อมูลเดิมของผู้สมัครพร้อมการตรวจสอบสิทธิ์ตามบทบาท (FR-REG-01, SEC-RBAC-01)
3. สร้าง validation logic สำหรับรูปแบบข้อมูลทั่วไปและระบบ highlight error field (FR-REG-02, FR-REG-03, NFR-USE-01)
4. สร้างการตอบกลับจาก backend เมื่อข้อมูลผิดพลาด เพื่อยกเลิกการบันทึกและคงค่าเดิมไว้ (FR-REG-03, AC-REG-02)
5. สร้าง transaction สำหรับ update applicant + insert AuditLog พร้อม log ของผู้แก้ไข วันเวลา ค่าเดิม/ค่าใหม่ (FR-REG-04, FR-REG-05, DOM-AUD-01, DOM-TXN-01, AC-REG-01)
6. สร้างปุ่มยกเลิกและคืนค่าข้อมูลเดิมพร้อมปิดฟอร์มโดยไม่สร้างประวัติ (FR-REG-06, AC-REG-03)
7. ทดสอบ end-to-end ตาม AC-REG-01 ถึง AC-REG-03 และปรับการแสดงข้อความ/ข้อผิดพลาดให้สอดคล้อง
