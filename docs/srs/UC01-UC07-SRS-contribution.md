# SRS ส่วนรับผิดชอบ: UC-01 และ UC-07

**โครงการ:** ระบบบริหารจัดการโครงการค่าย
**รายวิชา:** Software Requirement Specification and Management
**สถานะ:** Draft สำหรับนำไปรวม SRS ของกลุ่ม — ยังไม่ใช่ SRS Final ที่ทีมยืนยัน
**วันที่เตรียม:** 9 พฤศจิกายน 2026
**ผู้รับผิดชอบฟีเจอร์:** วรเมธ (ตาม `specs/README.md`)
**แหล่งจริงของข้อกำหนด:** `specs/001-community-location/spec.md` และ `specs/007-project-approval/spec.md`
**ข้อควรระวัง:** เอกสารนี้เป็นการรวบรวม ไม่เปลี่ยนหรือเพิ่ม Requirement ID

## 1. ขอบเขตระบบและผู้ใช้งาน

ระบบช่วยให้คณะกรรมการจัดการข้อมูลชุมชนและสถานที่ค่าย และส่งโครงการให้อาจารย์ที่ปรึกษาพิจารณาผลได้ โดยสถานะและประวัติการพิจารณาตรวจสอบได้

ผู้ใช้งานที่เกี่ยวข้อง:
- **คณะกรรมการค่าย:** จัดการข้อมูลชุมชนเฉพาะสถานที่ที่ได้รับมอบหมาย, ส่งโครงการ, รับทราบผลการพิจารณา
- **อาจารย์ที่ปรึกษา:** เปิดดูรายละเอียดโครงการที่รับผิดชอบ, อนุมัติ/ไม่อนุมัติ/ส่งกลับแก้ไข
- **ระบบยืนยันตัวตน (งาน UC-09):** เป็นส่วนพึ่งพาเพื่อยืนยันตัวตนและสิทธิ์ ไม่ได้รวมเป็นฟีเจอร์ใหม่ของ UC-01/07

## 2. UC-01 — บันทึกข้อมูลสถานที่และชุมชน

### 2.1 เป้าหมาย
เก็บข้อมูลชุมชน ข้อปฏิบัติพื้นที่ และข้อมูลติดต่อของผู้นำ/ผู้ดูแล เพื่อประสานงานค่าย และเชื่อมโยงกับสถานที่ค่ายที่รับผิดชอบ

### 2.2 Functional Requirements
| ID | ข้อกำหนดจาก spec.md |
|---|---|
| FR-01-01 | คณะกรรมการเปิดเมนูจัดการข้อมูลชุมชน |
| FR-01-02 | เลือกพื้นที่/สถานที่ค่ายที่เกี่ยวข้อง |
| FR-01-03 | ระบุรายละเอียดข้อมูลชุมชนและข้อปฏิบัติ (local rules) |
| FR-01-04 | กรอกข้อมูลผู้ดูแลพื้นที่ (ชื่อ ตำแหน่ง เบอร์โทรศัพท์ติดต่อ) |
| FR-01-05 | ตรวจสอบความถูกต้องและกดบันทึกข้อมูลเข้าสู่ระบบ |
| AF-01-01 | ข้อมูลช่องสำคัญไม่ครบ: แจ้งเตือนและระงับการบันทึก |

### 2.3 ข้อจำกัดและคุณภาพ
- **C-01 / ASM-01-01:** คณะกรรมการแก้ไขได้เฉพาะสถานที่ค่ายที่ตนได้รับมอบหมาย ห้ามแก้ข้ามค่าย
- **C-02:** ข้อปฏิบัติชุมชนรองรับข้อความ (Text) เป็นหลัก
- **QR-01:** การบันทึกและตอบสนองข้อมูลภายใน 2 วินาที
- **QR-02:** ฟอร์มใช้งานง่ายและแสดง Validation Error ชัดเจน
- **Out-of-Scope:** การประเมิน/อนุมัติพื้นที่ชุมชน, การส่ง SMS/Email ถึงผู้นำชุมชน

### 2.4 Acceptance Criteria
**AC-01:** Given คณะกรรมการเปิดหน้าจัดการข้อมูลชุมชนและเลือกสถานที่รับผิดชอบ; When กรอกชื่อชุมชน ชื่อผู้ดูแล เบอร์ติดต่อครบแล้วกดบันทึก; Then ระบบบันทึกข้อมูลผู้ดูแลเชื่อมกับสถานที่ และแสดงการยืนยันสำเร็จ

### 2.5 Open Questions (ยังไม่ใช่กฎของระบบ)
- **Q-01-01:** ต้องตรวจรูปแบบเบอร์โทรศัพท์/การตั้งชื่อชุมชนซ้ำหรือไม่
- **Q-01-02:** local rules ต้องแนบไฟล์หรือรูปภาพเพิ่มเติมหรือไม่

## 3. UC-07 — พิจารณาและอนุมัติโครงการ

### 3.1 เป้าหมาย
คณะกรรมการเสนอโครงการค่ายเพื่อให้อาจารย์ที่ปรึกษาตรวจสอบและลงผลการพิจารณา โดยระบบเก็บสถานะและประวัติการอนุมัติ

### 3.2 Functional Requirements (อ้างชุดแรกในหมวด 4 ของ spec.md)
| ID | ข้อกำหนดจาก spec.md |
|---|---|
| FR-07-01 | คณะกรรมการเปิดหน้าสรุปโครงการค่ายและส่งขออนุมัติให้อาจารย์ |
| FR-07-02 | อาจารย์ที่ปรึกษาเข้าสู่ระบบและเปิดตรวจรายละเอียดโครงการ |
| FR-07-03 | อาจารย์พิจารณา ลงมติอนุมัติ และบันทึกผล |
| FR-07-04 | ระบบบันทึกผลการอนุมัติ ประวัติ และเปลี่ยนสถานะโครงการ |
| FR-07-05 | ระบบแสดงสถานะล่าสุดให้คณะกรรมการรับทราบ |
| AF-07-01 | ส่งกลับแก้ไข: แจ้งคณะกรรมการพร้อมข้อเสนอแนะและส่งซ้ำได้ |
| AF-07-02 | ไม่อนุมัติ: บันทึกเหตุผลและยุติขั้นตอนโครงการ |

**ข้อบกพร่องใน Spec ปัจจุบัน:** หลังหัวข้อ Traceability มีหมวด Functional Requirements อีกชุดที่ใช้ ID FR-07-01..FR-07-05 ซ้ำด้วยความหมายต่างกัน และมี FR-07-06..07 เพิ่มมา **ต้องให้ทีมตัดสินและแก้ Spec ต้นทางก่อนรับรอง RTM** เอกสารนี้ไม่ตัดสินใจแทนทีม

### 3.3 ข้อจำกัดและคุณภาพ
- **C-01 / ASM-07-01:** การยืนยันตัวตนการอนุมัติใช้ Login Authentication และสิทธิ์อาจารย์
- **C-02 / ASM-07-02:** ส่งกลับแก้ไขแล้วแก้ข้อมูลและส่งขออนุมัติซ้ำได้
- **QR-01:** มีเพียงอาจารย์ที่ปรึกษาของโครงการเท่านั้นที่กดอนุมัติได้
- **QR-02:** ประวัติและข้อเสนอแนะต้องบันทึกถูกต้องและห้ามแก้ย้อนหลัง
- **Out-of-Scope:** อาจารย์แก้เนื้อหาโครงการโดยตรง; การอนุมัติงบประมาณมหาวิทยาลัย

### 3.4 Acceptance Criteria
**AC-07:** Given อาจารย์ที่ปรึกษาเข้าสู่ระบบและเปิดเอกสารโครงการ; When เลือก อนุมัติ/ไม่อนุมัติ/ส่งกลับแก้ไข พร้อมข้อเสนอแนะแล้วบันทึก; Then ระบบบันทึกสถานะและประวัติถูกต้องและแจ้งเตือนคณะกรรมการ

### 3.5 Open Questions
- **Q-07-01:** ต้องอนุมัติหลายระดับเพิ่มเติมในอนาคตหรือไม่ (ยังไม่รวมเป็นความต้องการปัจจุบัน)

## 4. ความเชื่อมโยงกับระบบและต้นแบบ

| ฟีเจอร์ | Dependencies | Prototype ที่เตรียม | ข้อจำกัด |

1. ทีมต้องปิดข้อขัดแย้ง FR-07-* และลงผลของ Q-01-01, Q-01-02, Q-07-01 ตามความเหมาะสม
